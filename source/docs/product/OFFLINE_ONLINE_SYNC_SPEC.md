# Offline and Data-Storage Behavior

Status: current implementation as of 2026-04-06.

This document describes the current data boundaries. **Firestore is not used by the app or Functions.** Firebase Authentication and Firebase Storage remain separate services.

## Data ownership

### Public shared opportunities

- `source/data/starter-opportunities.json` is the canonical public opportunity catalog in the owned GitHub repository.
- The app fetches it from the repository's `main` branch through `raw.githubusercontent.com` and caches the response locally.
- The bundled `source/data/starter-opportunities.json` remains the offline and network-failure fallback.
- A refresh does not write to GitHub. Staff edits are local drafts; the admin page exports the full JSON for review and a normal repository commit.
- Additional college-deadline records generated by the opportunity Function are cached locally. They do not become shared records unless explicitly reviewed and committed to the catalog JSON.

### Private per-user state

The app keeps user data on the current device; it does not publish personal state to GitHub or synchronize it through a database.

| Local key | Contents |
| --- | --- |
| `gatorguide:appdata:user:${uid}` | Signed-in profile, questionnaire answers, saved colleges, planner state, and app preferences for that Firebase Auth UID. |
| `gatorguide:appdata:active-user:v1` | Non-secret pointer to the signed-in local snapshot used at next startup. |
| `gatorguide:appdata:v1` | Guest/legacy app-data snapshot. |
| `gatorguide:opportunities:statuses:${uid}` | Per-account opportunity progress. Guest progress has its own guest key. |
| `gatorguide:roadmap:data:${uid}` | Per-account roadmap document. |
| `resume:${uid}`, `transcript:${uid}`, `avatar:${uid}`, `roadmap:${uid}:${docType}` | Local metadata for private documents and local file copies. |

A first sign-in on a device can promote the current guest app state into that account's local snapshot. Existing account data on that device is kept separate from other accounts. Sign-out retains the account snapshot but clears the active-user pointer. Account deletion removes the account's local snapshot, roadmap, opportunity statuses, and local document files, then removes Firebase Storage objects under that user's folder and deletes the Firebase Auth account.

There is no automatic cross-device sync. Users should use the app's explicit export/import flow to move supported data. Local-only files may not be portable unless included by that flow; an app uninstall or device loss can otherwise remove local-only data.

### Other remote services

- Firebase Auth is used only for account identity and authentication.
- Firebase Storage remains enabled for supported uploaded files. Unofficial transcripts and roadmap attachments are stored locally; a local file path is device-specific.
- College Scorecard, ZIP lookup, and Gemini are external API/Functions integrations. Their response caches are device-local.
- Error reports use the configured support webhook when available and otherwise remain in a bounded local queue. They are not stored in Firestore.

## Offline behavior

- Profile edits, questionnaire answers, saved colleges, opportunity progress, planner state, and roadmaps are local-first and persist in the account-scoped local snapshot or their registered local keys.
- Opportunity browsing uses the local catalog cache or bundled JSON when GitHub cannot be reached. The catalog cache is replaceable; it is not a publication queue.
- Generated deadline lookups require connectivity, but any returned public record is cached locally.
- Firebase Storage uploads may fail; flows that support it keep local files on the device. Local paths must not be treated as cross-device URLs.
- Scheduled notifications are device-local and are rebuilt from the local app state.

## Rate-limit and cost controls

AI usage and support-request rate-limit counters are process-memory safeguards, not durable accounting. Cloud Function restarts reset those counters. The Gemini callable is limited to one instance to reduce split counters, but this is not a hard spend cap. Configure provider-side API quotas/budget alerts for authoritative cost limits.

## Historical Firestore data

The app no longer reads or writes Firestore, and Firestore rules/emulator configuration have been removed from this repository. This code change does **not** migrate or delete records already stored in a Firebase project by an older app version. Cloud-only profile, saved-college, roadmap, opportunity-status, and chat records are not loaded by this version; any copies already present in the device's local snapshot remain local. Deleting a Firebase Auth account in this version does not purge historical Firestore documents. Review and securely export any needed legacy records before deploying, then separately remove old collections in the Firebase project only if deletion is desired. There is no automatic migration or remote purge in this change.
